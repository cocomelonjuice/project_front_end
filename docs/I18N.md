# Internationalization (i18n)

Strings use [react-i18next](https://react.i18next.com/). Locale JSON lives in `src/locales/en.json` and `src/locales/vi.json`.

## Avoid `ReferenceError: t is not defined`

The hook must run in **the same component** that calls `t` or uses `i18n`:

```tsx
import { useTranslation } from 'react-i18next';

function MyModal() {
  const { t, i18n } = useTranslation(); // required if you use t or i18n below
  // ...
  return <Dialog key={i18n.language}>...</Dialog>;
}
```

- **`import { useTranslation }` alone does not define `t`.** Always destructure from `useTranslation()`.
- Use `key={i18n.language}` on MUI `Dialog` (or similar) when labels float labels don’t update on language change.

## Checklist when adding translations

1. Add keys to **both** `en.json` and `vi.json`.
2. Call `useTranslation()` in the component that uses `t` / `i18n`.
3. Run `npx tsc --noEmit`.
4. Manually switch language and open the changed UI once.

## Quick audit (PowerShell, from repo root)

Lists `.tsx` files that call `t('...')` but **never invoke** `useTranslation()` (must print **nothing**).  
**Important:** `import { useTranslation }` alone is **not** enough — the file must contain the literal `useTranslation()` call.

```powershell
Get-ChildItem -Recurse -Filter *.tsx src | ForEach-Object {
  $raw = Get-Content $_.FullName -Raw
  if ($raw -match "\bt\(['`"]") {
    if ($raw -notmatch "useTranslation\(\)") { $_.FullName }
  }
}
```
